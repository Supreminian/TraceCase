# SummerTheCat 产品需求文档

- 文档版本：V0.1
- 日期：2026-10-27
- 状态：测试基线草案，含待澄清需求
- 产品形态：macOS 桌面宠物及 AI 文字对话应用
- 使用目的：验证需求提取、测试用例生成、歧义识别、人工审核及导出流程

## 1. 背景与目标

SummerTheCat 是一只常驻桌面的虚拟猫。用户可以与它进行鼠标互动、观看动作，并打开对话窗口与 AI 交流。本版本围绕桌宠展示、文字对话、模型连接设置和异常反馈建立可验证的需求基线。

本文依据现有 SummerTheCat 使用说明和 Gemini 接入说明整理。历史说明中存在不同版本的行为差异，无法确认的规则集中列在“待澄清需求”中，不作为已确定规则使用。

测试使用虚构昵称及普通示例文本，不输入真实个人信息、密钥或敏感业务数据。AI 回复用于陪伴交流，不承诺内容始终正确。

## 2. 范围

### 2.1 本次范围

- 桌宠显示、移动、暂停及鼠标互动。
- 对话窗口的打开、关闭、布局与输入。
- Google Gemini / OpenAI 连接设置及文字流式对话。
- 会话上下文、停止生成、失败重试及新建对话。
- 模型凭据保存和错误反馈。

### 2.2 非本次范围

- Windows 客户端、账号注册、多人共享和云端聊天记录同步。
- 语音输入、语音通话、文件上传及图像理解。
- 支付、订阅、自动开通付费额度。
- 修改 macOS 系统全局光标或安装系统级光标替换工具。

## 3. 角色与外部依赖

| 标识 | 角色或依赖 | 职责 |
| --- | --- | --- |
| ROLE-01 | 本机用户 | 操作桌宠、配置连接、发送消息和管理当前对话 |
| EXT-01 | 模型服务 | 接收经用户发送的对话请求并返回文本或错误 |
| EXT-02 | macOS 钥匙串 | 保存模型 API Key |

本次不设置管理员角色，也不定义账号权限层级。模型服务是否可用取决于用户所配置的凭据、模型权限、网络和服务额度。

## 4. 核心用户流程

1. 用户启动桌宠，在桌面上看到猫。
2. 用户双击猫，或从菜单打开对话。
3. 尚未配置模型时，用户进入连接设置，选择服务、输入密钥及模型名称。
4. 用户可以执行一次“验证对话”，确认连接结果，然后保存设置。
5. 用户输入文字并发送，界面展示生成状态和流式回复。
6. 用户可以继续追问、停止生成、重试失败请求或新建对话。
7. 用户关闭对话窗口后，桌宠继续运行；再次打开时恢复当前进程内的会话。

## 5. 确定的功能与业务规则

### REQ-PET-001 桌宠暂停与恢复

用户可以通过菜单暂停或恢复桌宠动画。暂停后动画保持暂停状态；打开对话窗口不应自动解除暂停。用户主动选择恢复后，桌宠才恢复动作播放。

### REQ-PET-002 对话入口

用户可以通过双击猫、菜单栏中的“和夏天聊聊…”或猫的右键菜单打开对话。重复执行打开操作时，应展示已有对话窗口，不创建多个独立聊天窗口。

### REQ-PET-003 对话窗口位置

对话窗口默认显示在猫头部的右上方，随猫的位置和缩放变化调整。右侧空间不足时，窗口改到左侧。窗口应保持在屏幕可见区域内。多屏跨屏时的具体归属规则尚未确定，见 OPEN-01。

### REQ-PET-004 对话关闭与恢复

点击对话窗口关闭按钮或按 Esc 收起对话。收起后桌宠进程继续运行。再次打开对话时保留当前进程内已有消息。关闭窗口与正在生成请求之间的关系见 OPEN-02，不得自行推定停止或继续请求。

### REQ-CHAT-001 输入与发送

输入框最多接受 1,000 个字符。空白消息不得发送。按 Enter 发送消息，按 Shift+Enter 插入换行。中文输入法正在选择候选词时，Enter 仅用于确认候选词，不得误发消息。字符计数口径及超长文本处理方式见 OPEN-03。

### REQ-CHAT-002 防止重复发送

同一对话正在生成回复时，不允许再次提交消息。用户连续点击发送按钮或连续按 Enter，不得为同一提交创建多个模型请求。停止生成或本次请求结束后，恢复发送能力。

### REQ-CHAT-003 流式生成与停止

模型返回文本后，界面逐步展示回复，不必等待完整回复后一次性显示。生成过程中用户可以点击“停止”。停止后本次请求不得继续向界面追加回复，并且用户可以再次发送消息。停止时已显示的部分回复如何保存及是否进入后续上下文，见 OPEN-04。

### REQ-CHAT-004 连续对话与新建对话

用户在同一会话中继续发送消息时，应携带当前输入、选定的完整历史对话轮次及系统指令。用户选择新建对话后，清空当前窗口的会话内容，后续请求不得携带上一会话的历史内容。历史轮次选取和长度裁剪规则见 OPEN-05。

### REQ-CHAT-005 会话保存边界

聊天记录只保存在当前应用进程的内存中，不写入本地聊天记录文件。退出应用后不恢复上一进程的消息。此规则不影响模型连接偏好与密钥的独立保存。

### REQ-CHAT-006 请求失败反馈与重试

请求失败时，界面应给出用户可理解的错误反馈，至少区分无效密钥、模型不可用或无权限、额度或限流问题、网络连接问题。不得在错误文本中显示完整 API Key。用户可以主动重试失败请求；重试期间仍需遵守防止重复发送规则。自动重试次数及策略未定义，不得自行假定存在自动重试。

### REQ-AI-001 服务与模型配置

连接设置支持 Google Gemini 和 OpenAI，用户可以选择服务并设置该服务使用的模型。两种服务的密钥和模型偏好分别保存；修改其中一种服务的设置，不得覆盖另一种服务已保存的设置。具体可用模型以所选服务的实际权限为准，本文不固定模型名称或免费额度。

### REQ-AI-002 验证连接

用户可以在连接设置中执行“验证对话”。验证必须通过实际的短文本生成请求检查所选服务、密钥和模型的组合，并反馈成功或具体错误，不能仅凭密钥非空判断成功。界面需说明验证会消耗服务额度；验证不得自动开通付费服务或升级套餐。

### REQ-AI-003 切换服务或模型

切换模型服务或模型名称后，开始一个新会话。不得自动把原会话上下文发送给新选择的服务或模型。切换发生在生成过程中时，旧请求如何处理尚未明确，见 OPEN-06。

### REQ-SEC-001 密钥保护

API Key 通过原生连接设置界面录入，并保存在 macOS 钥匙串中。聊天展示层只能获取服务名称、模型名称以及是否已配置密钥的状态，不能获取完整密钥。密钥不得出现在聊天消息、普通日志、请求 URL 或错误反馈中。

### REQ-ANIM-001 对话动作过渡

桌宠未暂停时，打开对话后先完成当前动作，再进入歪头动作，随后循环播放等待动作。对话窗口可以先接收用户输入，不必等待动画过渡完成。AI 请求等待期间保持等待动作；回复完成后安排回正，再恢复常规动作。

若进入歪头动作前用户已关闭对话，取消尚未开始的歪头队列，当前动作仍应完整结束。若回正过程中再次打开对话，先完成回正，再安排进入歪头。不得直接截断正在播放的动作以跳到另一动作。

### REQ-INTERACT-001 逗猫棒互动

用户可以通过菜单开启或关闭逗猫棒。开启逗猫棒时同时启用鼠标互动，并切换到玩耍模式。只有启用逗猫棒时才能触发新的八方向挥爪动作。关闭逗猫棒后不得再触发新的挥爪动作，已开始的挥爪动作允许完整播放。

### REQ-INTERACT-002 逗猫棒显示状态

逗猫棒启用时，鼠标靠近猫的互动区域显示逗猫棒指针，离开该区域使用正常指针。桌宠暂停、隐藏、用户操作原生菜单、编辑聊天或拖动桌宠时，应隐藏动画逗猫棒指针。上述状态结束后，只有仍启用逗猫棒且鼠标位于适用区域时才恢复显示。互动区域的尺寸及边缘定义见 OPEN-07。

## 7. 验收原则

1. 对第 5 节确定规则逐项验证正常、边界和异常行为，保留需求编号及原文位置。
2. 中文输入法确认候选词不得误发；空白输入及生成期间重复发送不得产生新请求。
3. 服务或模型切换后，不得把上一会话上下文提交给新配置。
4. 检查无效凭据、权限不足、额度不足和断网场景，错误反馈可理解且不泄露密钥。
5. 检查关闭窗口与退出进程的差异：同一进程重新打开可恢复消息，退出重启后消息不恢复。
6. 对 OPEN-01 至 OPEN-08 的未决部分，正确结果是记录问题和依赖关系；不能用自行设定的数值、权限或行为代替答案。

## 8. 用于本次测试的示例数据

- 示例用户昵称：小夏。
- 正常消息：“你好，请给我一句关于今天写代码的鼓励。”
- 多轮追问：“把刚才那句话缩短一些。”
- 空白输入：空字符串、仅空格、仅换行。
- 边界输入：分别构造 999、1,000、1,001 个普通英文字符；复杂 emoji 的计数应等待 OPEN-03 确认。
- 连接异常：使用专用测试环境模拟无效密钥、无模型权限、限流和断网，不在文档中放入任何真实密钥。
