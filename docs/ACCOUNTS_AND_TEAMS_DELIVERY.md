# 账号与团队协作：本地交付说明

日期：2026-10-28。按已确认方案实现本地可运行版本；不代表完成公网部署或监管认证。

## 用户流程

- 打开 `http://127.0.0.1:8501/`，首次注册账号，再登录。
- 选择个人工作，或创建／申请加入团队。后续登录恢复最近仍有权访问的空间。
- 创建者自动成为唯一所有者。邀请码仅允许提交申请；管理员审核并从预设角色中选择后，申请人才成为成员。
- 创建项目、输入真实格式的 Markdown PRD；生成任务在后台运行，完成后可打开结果。用户侧不展示模型配置或 Prompt 版本选择。
- 逐条审核；退回须说明原因，系统自动提交该条修订任务。其他用例继续审核，已有批准保留。任务失败可重试；人工修订与模型结果冲突时保留人工版本。
- 所有当前用例通过、没有阻断澄清、没有正在修订的任务，并且当前角色有导出权限时，生成 CSV / Markdown 批准快照。
- 团队管理包括申请审批、预设角色、业务权限开关、成员移除、邀请停用、所有权转移和归档。所有者不能直接退出。

## 边界与验证

`accounts.py` 管理 Argon2id 密码、12 小时服务端会话、登录及邀请码尝试限流。会话 Cookie 为 HttpOnly / SameSite=Strict；本机 HTTP 不设置 Secure，HTTPS 部署须设置 `SDLC_COOKIE_SECURE=1`。登录表单使用 Cookie 与隐藏字段的 CSRF 校验，并检查请求来源。

`secure_service.py` 是页面与下载的业务入口。`service.py` 是内部持久化引擎，仅供受控代码、离线维护和历史核心回归使用，不暴露为匿名接口。每个服务入口和每次业务数据库事务重新检查会话、空间成员关系及能力，资源还须属于所选项目和空间。认证身份替换请求中的自报 operator；审计保存用户 ID、当时显示名称以及事件关联。

批准下载通过同源网关重新授权，不使用 Streamlit 媒体缓存提供文件。降权／移除后旧链接失效。项目归属表禁止更改；请求幂等键包含用户与空间，原业务版本／审批／导出记录保持不可变。

后台任务用 SQLite 保存状态及证据、本进程最多两个线程执行。每空间同时最多两个任务、每日最多 100 次模型准入，全局最多 20 个活动／排队任务。格式修复最多一次，每次响应保留原文、配置、Prompt、用量和延迟。服务重启将未完成任务标为失败，不保存明文会话令牌，也不悄悄恢复生成。当前不是跨机器任务队列。

单条修订仅允许返回原用例编号的一个用例，重新检查来源、规则和有效问题，计算阻断状态。语义是否准确仍需人工审核；结构校验不等于证明模型没有捏造。

## 历史数据归属迁移

升级自动创建权限为 0600 的 `.before-accounts-*.sqlite3` 备份。原项目、运行、审批及导出字节保留。原项目没有账号归属时不出现在任何新账号的项目列表中，不能由首个注册者抢占。

用户注册并创建目标空间后，本机维护者可先查看目标（仅在可信本机终端操作）：

```bash
.venv/bin/python scripts/assign_legacy.py --list
```

明确选择项目与空间后执行：

```bash
.venv/bin/python scripts/assign_legacy.py --project PROJECT_ID --workspace WORKSPACE_ID
```

已有归属的项目拒绝重复分配。旧操作者标签保留为历史自报身份，不冒充新账号的认证审批；旧导出文件不改写。

## 运行与部署界限

```bash
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python scripts/run_google.py
# 或已自行设置模型环境变量时：
.venv/bin/python scripts/run_local.py
```

8501 为认证入口，8502 为仅绑定 loopback 的内部 Streamlit 服务；内部页面仍要求有效登录身份。不要再直接运行 `streamlit run app.py` 代替网关。可用 `SDLC_GATEWAY_PORT` / `SDLC_PRIVATE_PORT` 调整本地端口。

公网前仍需 HTTPS 终止、受信代理和主机配置、PostgreSQL、共享任务执行、容量／压测、备份恢复及部署安全评审。本轮提供本地受控协作功能及隔离测试，不声称已满足高并发生产部署条件。GitHub 第三方登录与显式账号绑定的后续实现见 [GitHub 登录说明](GITHUB_LOGIN.md)，需配置 OAuth App 后启用；邮件找回、项目级 ACL 和自定义角色仍未实现。

自动化测试使用临时数据库、虚构账号与模拟模型响应；浏览器验证使用另一份隔离数据库。它们不是实际模型质量评测结果。Git 仓库没有远端时，本地提交与 CI 配置不等于已经创建 GitHub Issue／PR 或跑过远端 CI。

## 退出登录交互修复

退出入口使用当前页原生 POST，一次点击撤销当前会话、清除登录及 GitHub 临时 Cookie，然后重定向到登录页并显示“已退出登录”。不再新开标签页或要求二次点击。退出校验绑定当前会话且不依赖可能提前过期的 CSRF Cookie；旧标签页不能用旧证明注销后来新登录的会话。

页面通过同源退出通知、可见时每 15 秒的会话检查，以及恢复／切回页面时的检查同步登录状态；通知不可用时也会在后续检查中回到登录页。同一账号会话轮换也会刷新旧页面。后端授权仍逐次校验；这些页面通知不替代授权。已登录用户访问登录页会回到工作台。直接 GET 退出 URL 不改变会话，避免链接预取或外站请求触发退出。
