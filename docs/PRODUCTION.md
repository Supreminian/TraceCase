# 上线设计补充：并发、安全与验收

状态：设计建议，待流量目标与部署环境明确后实施；不是已完成的生产能力。当前 105 项测试是功能与本地模拟接口测试，未执行负载测试或安全渗透测试。

## 1. 现状与上线边界

当前为单机 Streamlit + SQLite，模型请求在页面请求流程中同步执行。所有使用者共享数据库，操作者为自报标签；历史查询、原文和导出没有用户级授权。不能直接将监听地址改为公网后作为多人服务使用。

已具备：输入类型/编码/长度限制、严格输出校验、参数化 SQL、版本与状态校验、事务内导出门禁、请求幂等、历史快照、文本安全展示、CSV 转义、服务端环境变量密钥、远端 HTTPS、拒绝模型接口重定向、超时与响应大小上限。

尚缺：认证与对象级授权、租户隔离、共享限流与预算、异步任务、生产数据库、集中日志与告警、备份恢复演练、依赖扫描和流量验证。SQLite 的不可变触发器不防数据库管理员修改，应用内哈希不提供防篡改认证。

## 2. 分阶段结构

受控单人演示继续使用当前实现，仅本机访问。首次多人上线之前完成认证、资源归属和授权，再提供受控访问。

需要并发生成时采用：

```text
浏览器 → HTTPS 网关/身份认证 → 页面 + 后端 API → PostgreSQL
                                      ↓
                               持久化任务 → Worker → 模型服务
                                      ↓
                                校验结果与运行记录
```

业务校验、版本审批与导出服务继续沿用，持久化访问需要迁移；不能假设 SQLite SQL/事务实现可原样换库。Streamlit 可以暂作审核页面，长耗时调用移交 Worker。多人多副本使用共享数据库，不能共享网络盘上的 SQLite 文件。初期可用 PostgreSQL 任务表领取任务；流量和可靠性需求证明必要时再增加独立消息队列/Redis，避免提前维护多套基础设施。

## 3. 并发控制

### 提交与执行

- API 验证权限、输入、用户额度与预算后，在同一事务创建运行和任务，返回运行 ID/202；页面查询状态，不占用页面线程等待模型。
- 幂等键绑定可信用户/租户、请求内容和模型配置。相同键/相同内容返回同一运行，不同内容返回冲突。客户端重试沿用原键。
- Worker 以行锁或原子条件更新领取任务，记录租约、心跳、尝试编号和执行者；不在模型请求期间持有数据库事务或行锁。
- Worker 崩溃由租约超时恢复。任务投递按至少一次设计，入库通过唯一约束/比较更新防止重复生效；不宣称模型请求恰好一次或绝不重复计费。
- 超时后模型端可能仍完成请求。没有供应商幂等保证时，不立即自动重发；保留未知结果/尝试记录。可重试错误必须有上限、指数退避与抖动，尊重 Retry-After；认证、非法参数和校验错误不自动重试。
- 排队、执行中、完成、校验失败、调用失败、取消分别表达；取消排队任务不再执行，取消执行中的任务不承诺供应商停止计费。迟到响应保留在尝试记录，不能覆盖已终结运行状态。

### 流量与费用

- 网关按 IP 做粗限流，服务按用户、租户、模型做共享限流；所有副本共用计数。数据库原子预留额度，执行后按实际用量结算；用量未知时不能直接释放所有额度。
- 分别限制用户活跃任务数、全局模型并发、RPM/TPM、队列长度、等待时长、每日调用/Token/金额预算。单次输出上限不是整体预算。
- 队列满、额度不足或供应商持续失败时快速拒绝并说明原因，返回适当的 429/503；不靠无限排队吸收过载。按租户公平调度，避免单个用户占满容量。
- 价格未知时按调用数和 Token 预留限制，不声称金额预算已可靠执行；供应商硬支出限额作为额外保护。

容量估算：平均模型耗时 L 秒、Worker 并发 W、平均单次总 Token T，理论完成率受 `min(W/L, RPM/60, TPM/(60*T))` 请求/秒约束。需留余量并用真实分布复测，不能只按浏览器在线人数估算。

示例仅作规划：10 次生成/分钟、平均 30 秒，平均在途约 5 次；并发 5 已接近满载，可先评估并发 8，再核对供应商限额、Token 预算和实测 P95。以上不是测量结果或性能承诺。

### 审批与导出

- 修改、批准、退回使用条件更新与唯一约束，同时检查当前版本和状态；冲突返回 409，不能最后写入覆盖。
- 导出事务固定当前版本清单、有效批准事件及问题状态；并发修订要么排在该快照之后，要么导致导出冲突，不允许拼接不同时间点的版本。
- 所有审核操作从认证上下文取操作者，不信任客户端提交的 operator；异步任务不能继承任意用户传入的权限。
- 历史列表分页且只返回摘要，详情按需读取；目前 list_runs 读取全部输入/输出的方式需要调整。为资源归属、时间、任务状态和事件查询建立索引。

## 4. 安全设计

| 边界 | 上线前要求 |
| --- | --- |
| 身份 | 接入 OIDC 或受信任认证网关；校验令牌签发者、受众、有效期。生产移除自报身份作为权限依据 |
| 对象授权 | 每个运行、用例、问题、事件和导出绑定所有者/租户；每次读写与下载都检查权限，随机 ID 不代替授权 |
| 角色 | 发起、审核、管理权限分别授权；是否要求审核人与发起人分离由业务明确，不默认宣称双人复核 |
| Web 会话 | HTTPS、安全 Cookie、CSRF/Origin 校验、WebSocket 会话校验；CORS 仅允许指定来源，不能把 CORS 当身份验证 |
| 模型出网 | 服务地址由管理员配置且使用允许列表；阻断云元数据、链路本地和非授权内网目的地，防 DNS 重绑定；本地推理仅走明确授权目标。HTTPS 与禁重定向本身不足以防 SSRF |
| 输入与输出 | 网关与应用双层大小限制，限制模型响应和解析深度/资源；PRD/模型内容只作数据，不执行脚本、工具或生成 SQL；输出仍需语义审核 |
| 密钥 | 生产密钥放密钥管理服务/受控运行环境，按服务分权和轮换；日志/异常/配置导出不得含认证头或密钥 |
| 数据 | 原文、模型输出、审批和导出都按同一敏感级别管理；明确外部模型的数据处理范围、存储/备份加密、保留期限与授权删除流程 |
| 导出 | 下载经过授权，可采用短期签名链接；对象存储私有，禁止公共桶；继续做公式、HTML 与文件名转义 |
| 运维 | 最小数据库权限、非 root 运行、依赖锁定与漏洞扫描、TLS、管理端点隔离；日志脱敏，禁止直接记录完整请求和 PRD |

生产审计追加记录可信主体、时间、对象、动作、结果、请求 ID；重要审计可复制到独立受限存储。管理员操作也需留痕，但这仍不是监管认证。

## 5. 监控与上线验收

指标至少包括：提交与查询 P95/P99、任务排队/执行耗时、队列深度、活跃 Worker、429/超时/失败率、JSON/Schema 失败率、数据库锁等待、连接池占用、预算余额、Token 与已知费用。业务事件用 run_id/attempt_id 串联，不把敏感原文作为监控标签。

在部署环境与模型限额明确后设定验收目标。候选首轮负载为 100 个在线会话、10 次生成提交/分钟；入队 P95 < 500ms、审核/查询 P95 < 1s 仅作待验证目标。真实模型耗时单独统计，不能混入入队响应并声称秒级生成。

上线前必须验证：

1. 使用可控延迟模拟模型进行稳定负载、突发和长时间测试，记录资源配置与实际分母，再做小规模真实供应商验证。
2. 两个用户并发修订/批准同一版本时仅一个合法转移生效；审批与导出交错不绕过门禁。
3. 跨用户/租户访问、修改或下载运行和导出均被拒绝，不能枚举他人历史。
4. 重复提交、Worker 崩溃、租约过期、429、长超时、迟到响应和队列满不会丢记录或产生重复有效审批。
5. SSRF、提示注入、HTML/CSV 注入、超大输入、恶意 JSON、泄露异常与会话伪造均有针对性测试。
6. 数据库/对象存储备份与恢复演练完成，回滚与密钥轮换流程可执行；RPO/RTO 由业务确认后测量。

当前并未实现以上生产架构，也没有压测结论。优先顺序：认证/资源授权 → 数据库与异步任务 → 配额限流 → 部署监控与恢复 → 压测和安全验收。
