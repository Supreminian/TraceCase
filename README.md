# TraceCase · PRD 分析与测试复核

输入产品需求文档，提取功能、角色、业务规则和待澄清问题，生成有来源引用的测试用例，人工审核后导出 CSV / Markdown。支持不同业务领域，不要求 PRD 使用固定模板或自行编写段落编号。

界面用独立卡片、模块色与步骤导航区分需求输入、分析结果、澄清、人工审核和批准导出；账号与工作空间、项目切换放在侧栏。模型选择、地址及参数在后台配置，不占用用户操作流程。

## 使用流程

1. 注册并登录，选择个人空间或创建／申请加入团队，再创建或选择项目。操作身份来自登录账号；退出在当前页一次完成并返回登录页，其他标签页同步失效。
2. 粘贴 Markdown 或上传 UTF-8 `.md` / `.markdown` 文件，点击“生成测试用例”。
3. 系统使用唯一的通用需求 Prompt 分析 PRD、生成用例并校验。可计算的澄清状态自动整理；格式或引用仍有错误时最多自动修复一次，无需用户再次点击。原调用与修复调用分别留存，不循环重试。
4. 页面展示用例、功能、角色、规则和澄清问题。JSON 与原始响应默认折叠；模型配置由维护者管理，不出现在用户页面。
5. 逐条通过、退回或修改。通过说明可快速选择，退回需填写原因；提交后跳到下一条待审核用例。
6. 退回后后台只重新生成该条用例的新版本，未改用例的批准保留；可重试或人工修订。全部满足审批条件后导出批准快照。

产品界面及生产模型适配器不提供固定样例或回放模式。历史运行、审批与导出记录保留；隔离回归输入仅在 `tests/fixtures/` 中，生产代码不导入测试模块。

## 启动与模型配置

需要 Python 3.12：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
export GEMINI_API_KEY='在本机设置，不要提交 Git'
.venv/bin/python scripts/run_local.py
```

本机已有 SummerTheCat 的 Gemini 钥匙串凭据时，可使用 `.venv/bin/python scripts/run_google.py` 启动。凭据只读入进程环境，不复制到项目文件。应用地址为 `http://127.0.0.1:8501`。

- Google：`GEMINI_API_KEY`（或 `GOOGLE_API_KEY`），`GEMINI_MODEL` 指定模型。
- 兼容接口：由维护者设置 `SDLC_MODEL_PROVIDER=compatible`，并配置 `SDLC_MODEL_URL`（完整 Chat Completions 地址）、`SDLC_MODEL_NAME`、`SDLC_MODEL_API_KEY`。服务层默认需要兼容接口时设置 `SDLC_MODEL_PROVIDER=compatible`。
- `SDLC_MODEL_TIMEOUT` 默认 180 秒，可设 1–300 秒；`SDLC_MODEL_MAX_TOKENS` 默认 32768，可设 128–32768，仍受服务端上限约束。
- `SDLC_DB_PATH` 默认 `data/sdlc.sqlite3`。应用读取环境变量，不自动加载 `.env` 文件，`.env.example` 仅供配置参考。

每次点击生成最多调用模型两次，实际用量和可能的费用由服务商项目决定。超时、限流、内容过滤或达到输出上限不会按相同参数循环重试；页面说明原因并保留记录。不能保证外部模型永远可用或每份需求都能一次生成成功。

输入限制为文件 100 KiB、正文 20,000 个 Unicode 字符。请使用虚构或脱敏的需求，不在 PRD 中输入密钥。

## GitHub 登录

已加入 GitHub 登录和已有账号的显式绑定，复用原有个人／团队空间及权限。需由维护者配置 `GITHUB_CLIENT_ID`、`GITHUB_CLIENT_SECRET`、`GITHUB_REDIRECT_URI` 并重启；未配置时按钮显示暂不可用，保留密码登录。详见 [GitHub 登录配置与验证](docs/GITHUB_LOGIN.md)。

## 头像与个人资料

登录后点击侧栏最底部的头像账号卡片进入个人资料页；通过页内菜单切换个人资料、登录账号与绑定、修改密码和退出登录。退出模块需再次确认才会注销。资料页可修改显示名称、个人简介（最多 500 字符）及头像，登录账号不变。头像接受 2 MiB 以内的静态 PNG、JPEG、WebP；服务端验证实际图片内容，居中裁切为 256 × 256 PNG，并移除图片元数据。可勾选“恢复默认头像”；不选文件则保留现有头像。头像与简介保存在 SQLite，头像接口仅返回当前会话自己的图片，不使用外部头像服务。

多页面同时编辑使用资料版本检测，旧页面不能静默覆盖新资料。修改显示名称只影响之后的显示和新操作记录，不改写历史审批事件。账号数据库升级至版本 5 时自动备份并新增资料表，保留现有账号、会话和项目归属。

## 审核与追溯

- 唯一通用生成 Prompt 内部标识为 `GENERAL-R1`，用户不需要选择版本；历史记录中的旧标识不改写。审核修订和校验修复属于操作类型，复用同一个通用需求约束。
- 用例分类支持正常、边界、异常、安全、性能、易用性、兼容性及实际业务分类，不因出现 `security` 等分类拦截整份结果。
- 需求本身的未知条件进入澄清流程。问题不影响执行时可保留为有理由的补充核对项；明确阻断的问题不能跳过审批或批准导出。
- 问题与用例无需重复关联规则的全部来源。页面区分直接引用和经规则追溯的来源，并提示人工核对语义。
- 派生状态的整理保留前后差异；原始模型响应、输入摘要、配置、Prompt、用量和审批事件均保存。未知引用、重复编号、无法解析的结构仍须纠正，不以编造规则换取通过。
- 规则尚无关联用例属于覆盖质量提示，不丢弃其他有效用例；页面列出具体缺口，CSV 的 `coverage_note` 和 Markdown 的覆盖说明保留导出时的缺口。可审核、可导出已批准用例均不等于需求已完整覆盖。
- 旧的完整响应可本地重新校验，不调用模型，保存为关联新运行，旧数据不覆盖。新版本全部待审核，不继承批准。
- 项目分别管理输入、批次、用例、审核和导出。项目可归档；归档后保留历史读取和下载能力。

目前支持本地受控的账号、个人空间与团队协作，使用登录会话和服务端空间权限隔离。未完成公网高并发部署，不声称金融监管认证或企业级合规。详见 [账号与团队交付说明](docs/ACCOUNTS_AND_TEAMS_DELIVERY.md)，包括预设角色、下载授权、任务限制与历史数据迁移。

## 开发验证

```bash
.venv/bin/python -m pytest -q
.venv/bin/ruff check .
```

自动化测试隔离数据库并模拟网络边界，不使用真实密钥。真实模型验证需单独记录输入、结果、模型及用量，不能把模拟结果当成模型能力证据。`evaluation/` 保存早期离线评测准备材料，不接入当前用户生成流程，也不代表已完成质量评测。

认证入口为 `sdlc/gateway.py`，账号与团队为 `sdlc/accounts.py`，受权业务入口为 `sdlc/secure_service.py`，后台任务为 `sdlc/jobs.py`。

关键模块：`sdlc/domain.py` 输入与输出整理、`sdlc/prompts.py` 通用 Prompt、`sdlc/providers.py` 模型适配、`sdlc/service.py` 生成与审核服务、`sdlc/storage.py` 版本化存储、`sdlc/exports.py` 导出、`app.py` 与 `sdlc/project_ui.py` 界面。
